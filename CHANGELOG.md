# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),

## [Unreleased]

### Added

- Боковая панель чатов: ширина настраивается перетаскиванием
  правой границы (180–600 px), сворачивается кнопкой слева,
  состояние сохраняется в `localStorage`.
- Поле ввода: высота настраивается перетаскиванием верхней
  границы (140 px – 70 vh), состояние сохраняется в `localStorage`.
- Проверка правописания в поле ввода через встроенный механизм
  браузера (`spellcheck="true"`), с переключателем языка
  RU / EN / Авто.
- Спиннер рядом с кнопкой «Отправить», видимый во время
  генерации ответа.
- Короткая подсветка поля ввода в момент, когда оно становится
  доступным после завершения стрима.
- Автоматический возврат фокуса в поле ввода после завершения
  генерации — без ручного клика.
- Публичный метод `StreamManager.message_ids_with_content` для
  тестов и диагностики.

### Changed

- `OllamaService.stream_chat` теперь возвращает пары
  `(content, done)` вместо просто строк — флаг `done` из финального
  чанка Ollama прокидывается наверх.
- `StreamManager._run_worker` завершает стрим немедленно по
  получении `done=True`, а не ждёт закрытия HTTP-соединения httpx.
  Это разблокирует composer у пользователя на следующем же
  poll-тике, а не через несколько секунд.

### Fixed

- Composer (кнопка «Отправить» и поле ввода) оставался
  заблокированным после завершения генерации до перезагрузки
  страницы. Причина: `htmx:afterSwap` эмитится на отсоединённом
  polling-элементе и не всплывает до `document.body`, а также
  ожидание EOF от httpx занимало лишнее время. Устранено
  сочетанием флага `done` от Ollama, `setInterval` для синхронизации
  состояния composer'а и возврата фокуса.
- Дублирование polling-элемента при `hx-sync="this:replace"`
  в связке с `hx-swap="outerHTML"` — убрано из
  `partials/message_polling.html`.
- Редактирование ответа модели: кнопка ✏️ больше не показывается
  у assistant-сообщений, а маршруты `/edit` и `/save` возвращают
  403 при попытке обратиться к не-user сообщению.

## [1.0.0] - 2026-09-18

Первый стабильный релиз.

### Added

- Локальный веб-интерфейс для моделей Ollama: чаты, сообщения,
  вложения.
- Стриминг ответов модели через polling (700 мс).
- Загрузка `.md` / `.txt` в чат как вложение. Содержимое уходит
  модели один раз system-сообщением в начале промпта.
- Экспорт любого сообщения в `.md`-файл.
- Автоматическое имя чата по первому сообщению.
- Кнопка мягкой остановки генерации.
- Возобновление polling после перезагрузки страницы.
- Markdown в режиме чтения, редактирование в textarea.

### Security

- XSS-защита: Markdown рендерится с `escape=True`, сырой HTML из
  ответов модели и загруженных файлов экранируется.
- CSRF-защита на всех POST-запросах через токен в сессии.
  HTMX подставляет заголовок `X-CSRFToken` автоматически.
- Защита от DNS rebinding: Host allow-list (`127.0.0.1`,
  `localhost`, `[::1]`), fail-closed на пустой Host.
- `SECRET_KEY` создаётся через `os.open(O_CREAT|O_EXCL, 0o600)` —
  без окна world-readable. Запись завершается `fsync`.
- Ограничения на размер файлов и общий объём вложений.
- Атомарная резервация слота стрима — второй запрос в тот же чат
  получает 409.

### Fixed

- При отказе `try_reserve` (гонка между пре-чеком и резервацией)
  откатываются оба сообщения — user и placeholder-assistant. Раньше
  user-сообщение оставалось без ответа.
- `stop_generation` не обнуляет уже видимый контент.
- Polling не теряется при перезагрузке страницы во время стрима.
- Ошибки 4xx от HTMX-эндпоинтов доставляются в UI через
  `HX-Retarget` и `beforeSwap`-override.

### Известные ограничения

- Отмена генерации — мягкая. Ollama прекращает работу в течение
  1–2 секунд после закрытия соединения клиентом. Гарантированная
  остановка — перезапуск `ollama serve`.
- Один воркер WSGI. `StreamManager` хранит стримы в памяти процесса.
- Аутентификации нет. Приложение слушает только `127.0.0.1`.
